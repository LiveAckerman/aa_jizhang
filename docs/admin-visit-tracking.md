# 后台访问统计的数据口径

“访问数”是小程序每次触发 `App.onShow` 成功上报的一条事件：冷启动和从后台返回前台各计一次。它不是页面 PV，也不是 API 调用次数。

事件使用小程序本地保存的随机安装标识和每次事件的 UUID；不采集 IP、地理位置或设备指纹。登录 JWT 有效时服务端才关联用户，客户端不能提交用户 ID。网络失败、超时或不支持安全随机接口时不重试、不提示用户，因此统计不承诺无漏报。

采集接口使用两层进程内限流：同一匿名安装标识每分钟最多 12 次，单个服务进程每分钟最多 3000 次。服务仅保留最近 1000 个匿名标识的限流窗口并定期清理过期项，既不存 IP，也不会让限流内存随访客数量无限增长。多实例部署时各进程独立计数；这里的目标是用低成本保护采集入口，不提供跨实例的精确配额。

`analytics_collection_status.started_at` 是迁移部署到服务端后采集功能启用的时间。后台必须显示该时间，并将其之前的访问指标标为“未采集”；小程序新版本尚未发布时没有事件，不能解释为没有访问。历史日志不用于补造访问数据。

本次迁移仅新建 `app_visit_events` 和 `analytics_collection_status`。生产环境应按既有迁移发布流程执行；本地/测试库如需验证，只应执行这一个新迁移，避免把旧迁移的影响混入验证结果。
