### 1. ✅ 修复结算逻辑缺陷（严重）

**问题描述：**
- 创建结算记录后未调用 `complete()` API
- 导致结算状态永远为 `pending`，用户以为已结清但实际未生效

**修复方案：**
```javascript

await api.completeSettlement(settlement.id)

// 批量结算：使用新的batch API，一次性创建为completed状态
await api.batchCreateSettlement({
  bookId,
  settlements: [...]
})
```

### 4. ✅ 添加批量结算API（重要）

**问题描述：**
- 前端串行创建多个结算记录，无事务保护
- 部分失败会导致数据不一致和残留

**修复方案：**
```typescript
// settlement.service.ts - batchCreateAndComplete()
async batchCreateAndComplete(userId, dto) {
  const queryRunner = this.dataSource.createQueryRunner()
  await queryRunner.startTransaction()
  
  try {
    // 批量创建结算记录，直接标记为completed
    for (const item of dto.settlements) {
      const settlement = this.settlementRepo.create({
        ...item,
        status: 'completed',
        completedAt: new Date(),
      })
      await queryRunner.manager.save(settlement)
    }
    await queryRunner.commitTransaction()
  } catch (error) {
    await queryRunner.rollbackTransaction()
    throw error
  }
}
```

**新增接口：**
- `POST /api/settlements/batch` - 批量创建并完成结算

**新增文件：**
- `packages/server/src/settlement/dto/batch-create-settlement.dto.ts`

**影响文件：**
- `packages/server/src/settlement/settlement.service.ts`

## ⚠️ 注意事项

### 1. 数据库迁移
如果生产环境已有 `status='pending'` 的结算记录，需要手动处理：
```sql
-- 查看待结算记录
SELECT * FROM settlements WHERE status = 'pending';

-- 清理或标记完成（根据业务决定）
UPDATE settlements SET status = 'completed', completed_at = NOW() 
WHERE status = 'pending';
```

### 2. 向后兼容性
- 旧的单笔结算逻辑已修复，兼容现有流程
- 批量API为新增，不影响旧代码
- 成员移除增加了校验，可能导致之前可移除的现在不可移除（这是正确的）

### 3. 性能影响
- 批量结算使用事务，会持有锁，但影响可控（通常<1s）
- 成员移除需要计算余额，当账本有数千笔交易时可能较慢（建议后续优化）
