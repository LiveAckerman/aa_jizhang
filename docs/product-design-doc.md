## 🎯 产品定位

### 核心定位
一款专注于**多人场景分账**的移动记账应用，主打旅行、聚餐、活动等多人协作记账场景，同时支持个人私密记账需求。

### 目标用户
- **主要用户：** 18-35岁年轻群体
- **用户特征：** 
  - 喜欢旅行、社交活动
  - 注重生活品质
  - 对账目清晰度有要求
  - 经常与朋友AA消费

### 使用场景
1. **旅行场景（核心）：** 多人一起旅行，需要记录和分摊各种费用
2. **聚餐场景：** 朋友聚餐，统一买单后需要AA分账
3. **合租场景：** 室友合租，共同分担房租水电等费用
4. **活动场景：** 组织活动，需要收集和分摊活动费用
5. **情侣场景：** 情侣间记录共同支出

## 💡 核心创新点

### 1. 双账本模式（核心差异化功能）

**痛点：**
在多人旅行或活动中，用户既有需要分摊的共享支出（如门票、餐饮），也有自己的私密支出（如买纪念品、个人消费）。传统记账app要么只能记共享账，要么需要创建两个账本分别管理，非常麻烦。

**解决方案：**
在同一个账本内实现**「共享账」**和**「私密账」**双轨记账模式。

```
【北京旅游】账本
├─ 共享账（所有成员可见）
│  ├─ 故宫门票 ¥200（4人平摊）👥
│  ├─ 午餐 ¥480（4人平摊）👥
│  └─ 打车 ¥60（4人平摊）👥
│
└─ 我的私密账（仅自己可见）
   ├─ 冰箱贴 ¥35 🔒
   ├─ 买零食 ¥28 🔒
   └─ 买明信片 ¥15 🔒

我的总支出 = 共享账中我的应付金额 (¥185) + 私密账总额 (¥78) = ¥263
账本显示的总支出 = 共享账总额 ¥740（其他成员看不到我的私密账）
```

**实现逻辑：**
- 记账时可选择「共享」或「私密」
- 共享账：所有成员可见，可选择分账方式和参与人员
- 私密账：仅自己可见，不参与账本总额统计（对其他成员而言）
- 统计页面清晰拆分：共享支出 + 私密支出 = 我的总支出

### 2. 智能分账算法

**功能：** 自动计算最优结算方案，最小化转账次数

**示例：**
```
原始欠款关系：
甲欠乙 ¥100
甲欠丙 ¥50
乙欠丙 ¥30

优化后：
甲付给丙 ¥150
乙付给丙 ¥70

从4笔转账优化为2笔
```

### 3. 多种分账模式

- **平均分摊：** 所有参与人平均分担（最常用）
- **按比例分摊：** 按设定比例分担（如按工资比例）
- **按份额分摊：** 按份数分担（如大人2份，小孩1份）
- **指定金额分摊：** 手动指定每人金额（如有人喝酒有人不喝）

### 1.5 账本自定义分组

允许用户把自己的账本组织成若干**自定义分组**（如「2024旅行」「家庭」「同事聚餐」），便于在账本列表中归类查看。
**分组维度（重要）：**
- 自定义分组为**个人维度**——每个用户各自组织自己看到的账本，互不影响；账本成员之间不共享分组结构，避免多人协作冲突。
- 与「状态分组（进行中/已结算）」正交：状态分组由系统按结算状态自动划分，自定义分组由用户手动组织，二者可并存。

**归属规则：**
- 一个账本最多属于**一个**自定义分组（单归属）；未设置时归入「未分组」。
- 删除分组时，其下账本回落为「未分组」，**不删除账本**。

**操作入口：**
- **创建分组：** 账本列表「创建」菜单 → 创建分组（名称必填，可选图标/颜色）；或在账本设置修改所属分组时新建。
- **编辑分组：** 长按账本列表的分组标题 → 重命名 / 删除。
- **修改账本归属：** 账本详情页 → 更多菜单 → 账本设置 → 所属分组，选择已有分组、新建分组或清除归属。

**当前实现：** 自定义分组已接入前后端。后端使用 `book_groups` 保存用户分组，并通过 `book_members.groupId` 保存每位成员自己的账本归属；没有单独的 `book_group_items` 表。

### 3.5 记账「位置 + 图片凭证」功能说明

记一笔时可选记录**位置信息**并附**拍照/图库图片**作为凭证。二者均为可选项，共享账与私密账通用。
#### 位置信息采集

支持两种方式，用户可自由切换：

- **自动定位（默认）：** 调用 `wx.getLocation`（`type: 'gcj02'`）获取当前经纬度并展示地点；进入记账页时可自动尝试。
- **地图选点：** 调用 `wx.chooseLocation` 打开地图，用户搜索/点选后返回 `name`（地点名称）、`address`（详细地址）、`latitude`、`longitude`。

**授权与降级：**
- 需 `scope.userLocation` 授权；`app.json` 需配置 `requiredPrivateInfos: ["getLocation", "chooseLocation"]` 及 `permission.scope.userLocation` 的说明文案。
- 用户拒绝授权时降级为「不带位置」，仍可手动点开地图选点；位置始终可清除，不阻塞记账保存。

#### 图片凭证采集与上传

- **采集：** 调用 `wx.chooseMedia`（`mediaType: ['image']`，`sourceType: ['camera', 'album']`，数量上限 9 张），支持**拍照**或**从相册选择**；本地压缩后逐张上传。
- **上传链路：** 小程序 → 后端上传接口 → Cloudflare R2。小程序端不持有 R2 密钥，图片经后端代理上传，后端返回公开 URL，URL 数组存入账单 `images` 字段。
- **实现参考：** 后端可复用 `scripts/generate-asset.js` 中的 R2 SigV4 上传逻辑（`uploadToR2`）与 `.env` 中的 R2 配置（`R2_*`、`R2_PUBLIC_URL`，公开 URL 依赖后者）。
- **当前实现：** 交易 controller/service、图片上传接口和记账页面均已接入；位置支持地图选点和清除，但自动定位尚未实现。

## 🔐 数据隐私说明

### 私密账的隐私保护机制

1. **数据存储：**
   - 私密账数据仅存储在用户自己的账户下
   - 使用独立的数据表，与共享账隔离
   - 加密存储（AES-256）

2. **接口隔离：**
   - 查询账本详情时，仅返回用户自己的私密账
   - 其他成员的接口请求完全获取不到私密账数据

3. **前端渲染：**
   - 私密账单带🔒图标明显标识
   - 私密账单使用不同背景色（深色）
   - 鼠标悬停提示「仅自己可见」

4. **统计隔离：**
   - 账本总览中不包含私密账金额
   - 仅在「我的统计」页面显示私密账支出

### 位置信息的隐私保护

- **用户可控：** 位置信息仅用于标注账单发生地点，完全可选；用户可随时清除，不带位置也能正常记账。
- **授权透明：** 采集前需用户授权 `userLocation`，并在授权弹窗中说明用途；拒绝授权不影响记账。
- **可见范围：** 位置随账单类型的可见范围一致——私密账的位置仅自己可见，与其他私密账数据一同隔离。

## 附录

### 附录A：分账算法详解

**问题：** 多人分账后，存在复杂的欠款关系，如何最小化转账次数？

**解决方案：** 使用贪心算法

```python
def minimize_transactions(debts):
    """
    debts: {person: amount}
    正数表示应收，负数表示应付
    """
    # 1. 计算每个人的净收支
    creditors = []  # 应收方
    debtors = []    # 应付方
    
    for person, amount in debts.items():
        if amount > 0:
            creditors.append((person, amount))
        elif amount < 0:
            debtors.append((person, -amount))
    
    # 2. 按金额排序
    creditors.sort(key=lambda x: x[1], reverse=True)
    debtors.sort(key=lambda x: x[1], reverse=True)
    
    # 3. 贪心匹配
    transactions = []
    i, j = 0, 0
    
    while i < len(creditors) and j < len(debtors):
        creditor, credit = creditors[i]
        debtor, debt = debtors[j]
        
        amount = min(credit, debt)
        transactions.append((debtor, creditor, amount))
        
        creditors[i] = (creditor, credit - amount)
        debtors[j] = (debtor, debt - amount)
        
        if creditors[i][1] == 0:
            i += 1
        if debtors[j][1] == 0:
            j += 1
    
    return transactions
```

**示例：**
```
输入：
甲: +150  （应收150）
乙: -100  （应付100）
丙: -50   （应付50）

输出：
乙 → 甲: 100
丙 → 甲: 50

总共2笔转账（最优）
```
